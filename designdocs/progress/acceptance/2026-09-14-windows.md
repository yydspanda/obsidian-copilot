### Paused-state Apply mismatch — source inspection, not live reproduction

The live Review button is enabled while the Bundle is user-paused. Source
inspection shows that `KnowledgeProductionReviewedApplyCoordinator.submit()`
persists acceptance before calling `IngestQueue.beginReviewApply()`. The latter
rejects the current user pause (startup recovery has a separate exception); the coordinator retries the same
handoff, then returns `recovery_required` after an accepted review if it still fails.
Thus a valid accepted proposal can become durable before user pause prevents the
Apply handoff, without reaching the Wiki transaction. Review capability checks
do not currently exclude this user-paused state.

This risk was not triggered against the real proposal. It is a separate workflow
finding, not evidence that the selection-feedback repair failed. No fix, Resume
or Apply was authorized by this confirmation of visual feedback.
